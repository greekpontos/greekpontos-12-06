### Задание 1
На лекции рассматривались режимы репликации master-slave, master-master, опишите их различия.

#### Ответ:

Основные различия между режимами репликации заключаются в распределении ролей для записи и чтения данных, а также в сложности архитектуры:

1. **Режим Master-Slave (Основной - Ведомый):**
   * **Куда идёт запись:** Запись любых изменений (INSERT, UPDATE, DELETE) происходит строго на один сервер — **Master**.
   * **Откуда идёт чтение:** Чтение данных (SELECT) может происходить как с Master, так и со всех подключенных серверов **Slave**. Slave-серверы только копируют бинарные логи изменений с Master и воспроизводят их у себя.
   * **Плюсы:** Отлично масштабирует систему на чтение, прост в настройке и резервном копировании, нет конфликтов при записи данных.
   * **Минусы:** Если Master выходит из строя, система временно теряет возможность принимать записи, пока один из Slave-серверов вручную или автоматически не переведут в режим Master.

2. **Режим Master-Master (Основной - Основной):**
   * **Куда идёт запись:** Клиентские приложения могут одновременно записывать и изменять данные на **любом** из серверов. Изменения, сделанные на одном Master, автоматически синхронизируются со вторым Master.
   * **Откуда идёт чтение:** Чтение также доступно с любого сервера в архитектуре.
   * **Плюсы:** Высокая отказоустойчивость на запись. Если один Master «упадёт», второй продолжит полноценно принимать и записывать данные.
   * **Минусы:** Сложная настройка. Главная проблема — **конфликты репликации**. Если два пользователя одновременно изменят одну и ту же строчку на разных серверах, СУБД должна иметь сложную логику для разрешения этого конфликта (какое изменение считать правильным).
